## Three.js on ai-game.dev: findings

The two URLs you suggested returned HTTP 200 with an empty body (0 characters), so I could not read them. I did not retry. The tools catalog (https://ai-game.dev/docs/tools) has no Three.js section: it covers only Unity, Unreal and Godot.

**(1) MCP tool names: not stated.** The blog describes Three.js capabilities but names no tools. Its list, with my paraphrase:
- Status and logs: open pages, frame rate, console output, uncaught errors with stacks, compile errors.
- Screenshots of the game canvas after a rendered frame.
- The three.js scene tree and values the game exposes, "without extra game code".
- Input: keyboard, mouse, wheel, touch and gamepad, plus pause, step frames, and change time scale.
- Playtests: a scripted run of input, frame steps, checks and screenshots that ends in a PASSED or FAILED report.

Video recording and transform/material/texture editing are not mentioned. The catalog's 104 MCP tools cover only the other engines.

**(2) Connection to a running game.** The blog says the game runs in a "live panel" and is "a real browser view". The browser engine is not stated, and neither is how the agent attaches (injected script or otherwise). The starter projects are "a three.js + Vite + TypeScript project with nothing extra in it", and the agent "adds libraries when the game needs them". I found no statement that a code change is needed for the agent to connect.

**(3) Existing projects (Vite or plain HTML/ES modules): not stated.** The blog covers only creating new projects, from the app, the CLI (`/create-project threejs my-game --starter island`), or by asking the agent. Starters are Empty, Studio, Blueprint, Checker and Island. It also says the app can create a web prototype inside a Unity, Godot or Unreal project, in a WebPrototypes folder. Edits hot-reload through Vite.

**(4) Gaussian splats, Spark, custom shaders: not stated.** Neither page mentions them.

**(5) Linux or headless rendering: not stated.** The app downloads its own Node.js from nodejs.org and checks it against SHA-256. The blog says the game "can be opened anywhere a browser runs". It also describes hidden views for tests and a phone view via the app's remote link. No OS or headless details are given.
